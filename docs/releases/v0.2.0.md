# VHScribe v0.2.0

Released: 2026-08-16

VHScribe v0.2.0 brings the current hardened implementation into the public repository. The capture architecture remains deliberately simple: one FastAPI-supervised FFmpeg process owns the physical V4L2/ALSA devices, MediaMTX transports preview over WebRTC, and recordings stay on the server.

## Highlights

- **On-demand preview:** starts idle with capture hardware released; preview can be started/stopped explicitly and idles after the configured dashboard-heartbeat timeout. Active recordings are never governed by that timeout.
- **Stronger finalisation:** a completed file must contain video and audio and match configured video geometry, rational frame rate, sample aspect ratio, 4:3 display aspect, audio sample rate/channel count, and positive duration before promotion.
- **QC sidecars:** successful recordings get a `.mkv.qc.json` manifest with capture/build provenance, FFmpeg/probe evidence, validated invariants, warning/progress evidence, and final `verified` or `needs_review` state.
- **Optional fixity/full decode:** SHA-256 fixity is enabled by default. Full-file decode verification is opt-in because it can take roughly the duration of the tape.
- **Safer recovery:** requires video and audio, uses a temporary `.recovering.mkv`, never overwrites the source partial, cleans failed transitional output, and recognises an already recovered result.
- **Additional hardening:** recording start is rejected once shutdown begins, and the download endpoint only serves explicit completed media.

## Compatibility

Maintainer physical testing is an EasierCAP-branded adapter identified by Linux as MacroSilicon MS210x, using PAL 720×576 at 25 fps with 48 kHz stereo audio on Ubuntu Server 24.04/amd64. MacroSilicon hardware is a tested reference, not a hard dependency.

The NTSC 720×480 at 30000/1001 path and `linux/arm64` container build are covered synthetically; a real NTSC capture chain and physical ARM host remain unverified.

## Upgrade from v0.1.0

Back up `.env` and your capture directory, then:

```bash
git pull --ff-only
docker compose build --pull
docker compose up -d
./scripts/verify-installation.sh
```

Review `.env.example` for the new preview/QC options. Existing recordings are not rewritten.

## Known limitations

- The current master is H.264/yuv420p + AAC rather than a lossless archival codec.
- Real-hardware interlace/field behaviour and long moving-tape A/V drift still need controlled evidence.
- Physical NTSC capture is not yet maintainer-verified.
- There is no built-in authentication or TLS; keep VHScribe on a trusted host/LAN.
- Low-disk reserve handling and tighter MediaMTX publication permissions remain future hardening work.
